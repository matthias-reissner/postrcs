Ein kleiner, klarer Ablauf

Von Text zu Revision – mit SQL.

Die Anwendung steuert, wann eine Revision entsteht. Das Archiv selbst liegt als Wert in deiner Tabelle.

01

Archiv ablegen

Eine Spalte vom Typ rcs_archive hält ein RCS-Archiv pro Datensatz.

history rcs_archive
02

Änderung einchecken

rcs_checkin erzeugt die nächste trunk-Revision. Speichere den Rückgabewert.

UPDATE docs
SET history = rcs_checkin(
  history, inhalt, kommentar
);
03

Version abrufen

Checkout, Metadaten und Diff sind SQL-Funktionen – direkt abfragbar.

SELECT rcs_checkout(
  history, '1.1'
);

Direkt in PostgreSQL

SQL-Beispiele zum Kopieren.

Diese Beispiele laufen mit der installierten Erweiterung. Der Browser-Playground darunter ist davon unabhängig und simuliert nur den Ablauf.

Archiv anlegen

CREATE TABLE documents (
  id bigint GENERATED ALWAYS
    AS IDENTITY PRIMARY KEY,
  history rcs_archive NOT NULL
    DEFAULT ''::rcs_archive
);

INSERT INTO documents (history)
VALUES (rcs_checkin(
  ''::rcs_archive,
  E'Erste Zeile\n',
  'Erstellung'
));

Branch und Tag

UPDATE documents
SET history = rcs_create_branch(
  history, 'feature', '1.1'
)
WHERE id = 1;

UPDATE documents
SET history = rcs_branch_checkin(
  history, 'feature',
  E'Erste Zeile\nBranch\n',
  'Feature begonnen'
)
WHERE id = 1;

UPDATE documents
SET history = rcs_tag(history, 'release_1', '1.1')
WHERE id = 1;

Revisionen abfragen

SELECT rcs_head(history),
       rcs_checkout(history, 'feature'),
       rcs_diff(history, '1.1', 'feature')
FROM documents
WHERE id = 1;

SELECT name, revision, is_branch
FROM documents,
     LATERAL rcs_symbols(history)
WHERE id = 1;

Merge prüfen

SELECT (rcs_merge(
  history, '1.1', 'feature', 'stable'
)).*
FROM documents
WHERE id = 1;

In wenigen Schritten startklar

Installation für PostgreSQL 18.

Die vorkompilierte Demo ist für Windows x64 und PostgreSQL 18 gebaut. Die Extension wird anschließend in jeder Zieldatenbank einmal aktiviert.

01

Binärpaket herunterladen

Entpacke das Paket auf dem PostgreSQL-Server. Für andere PostgreSQL-Hauptversionen und Betriebssysteme ist ein passender Build erforderlich.

Windows x64 · PostgreSQL 18 herunterladen ↗
02

Dateien kopieren

In die PostgreSQL-Installationsordner kopieren. Dafür können Administratorrechte nötig sein.

$pg = "$env:USERPROFILE\PostgreSQL\18"
Copy-Item .\lib\postrcs.dll "$pg\lib\"
Copy-Item .\share\extension\* `
  "$pg\share\extension\"
03

In der Datenbank aktivieren

Verbinde dich mit der Zieldatenbank und führe das SQL einmal pro Datenbank aus.

CREATE EXTENSION postrcs;
i

Was wird installiert?

  • postrcs.dll – PostgreSQL-Funktionen
  • postrcs.control – Extension-Metadaten
  • postrcs--1.2.sql – SQL-Typ und API
  • postrcs--1.0--1.1.sql – Update von Version 1.0
  • postrcs--1.1--1.2.sql – Update auf 1.2

Dein Browser-Playground

Check-in. Checkout. Vergleichen.

Ändere den Text, checke Revisionen ein und sieh dir den Verlauf an. Deine Daten bleiben lokal in diesem Browser gespeichert.

✦

Interaktive Simulation: Dieses Playground verbindet sich nicht mit PostgreSQL. Es bildet den Text- und trunk-Workflow nach und erzeugt eine exportierbare RCS-Archivdatei. Zustand und Eingaben werden nur in diesem Browser gespeichert. Probiere Branches und SQL-Funktionen in einer echten Datenbank nach der Installation aus.

Gut zu wissen

Ein fokussierter erster Schritt.

PostRCS unterstützt trunk- und Branch-Revisionen, Tags, getrennte Diff-Hunks, Drei-Wege-Merges mit Konfliktmarkern und den Import/Export nativer RCS-Archive. Branches können von trunk-Revisionen erstellt, aber nicht verschachtelt werden. Nicht-leere Inhalte brauchen einen abschließenden Zeilenumbruch; Binärdateien werden nicht unterstützt.
